## Открытые пункты

_На момент заполнения плана открытых пунктов нет. Будут добавляться по мере реализации, если какой-либо шаг из `@ai/tasks.md` пропускается._

### [РИСК] JSON-LD и строгий CSP

- Причина: глобальный CSP (этап 2, routes/_middleware.ts) содержит `script-src 'self'` без `unsafe-inline` и nonce. В части браузеров это может блокировать инлайн `<script type="application/ld+json">`, который рендерит components/JsonLd.tsx (этап 3).
- Ссылка: `@ai/tasks.md`, этап 3, шаг 2 (JSON-LD); этап 6, шаг 6 (подключение JSON-LD на страницах).
- Критерий готовности: на странице поста JSON-LD валиден (validator.schema.org) и не блокируется CSP - например, через CSP-hash для ld+json или подтверждение, что data-блоки не подпадают под script-src в целевых браузерах.

### [ОТЛОЖЕНО] Core Web Vitals на дашборде производительности

- Причина: F15 допускает сбор CWV "if available via browser API in admin", но PerformanceObserver в админке мерил бы сам админ-UI (гидратированные островки), а не публичные страницы - метрика вводила бы в заблуждение. Остальные метрики F15 (response time, cache hit rate, page size, KV latency) реализованы.
- Ссылка: `@ai/tasks.md`, этап 11, шаг 1 (F15).
- Критерий готовности: осознанная потребность в CWV публичного сайта и способ их собрать (например, RUM-эндпоинт, принимающий beacons с публичных страниц, при сохранении нуля JS на публичке это невозможно - потребуется отдельное решение).

### [ОТЛОЖЕНО] Сборка Docker-образа не прогонялась

- Причина: на рабочей машине нет Docker-демона, поэтому `docker build` по Dockerfile этапа 13 не выполнялся. Каждый шаг проверен по отдельности: deno install по deno.lock, deno task build, deno task start со scoped-правами (все зеленые локально).
- Ссылка: `@ai/tasks.md`, этап 13, шаг 1.
- Критерий готовности: `docker build -t oxygen-blog .` проходит; контейнер стартует с env-переменными, отвечает на :8000, данные переживают рестарт через volume.

### [ОТЛОЖЕНО] Проверка гидратации островков в браузере

- Причина: smoke-тесты через curl покрывают только серверный рендер и API; реальная гидратация (события кнопок тулбара, модал медиатеки, debounce-превью) в браузере не проверялась ни на одном этапе с островками (4, 5, 7).
- Ссылка: `@ai/tasks.md`, этап 7 (MarkdownEditor), этапы 4-5 (SlugField, ConfirmDelete).
- Критерий готовности: ручной или автоматизированный (Playwright) прогон ключевых сценариев админки в браузере перед релизом MVP.

### [ЗАМЕТКА] Vite падает из-за файла NUL в корне (исправлено 2026-09-03)

- Симптом: со страницы Performance (и любой другой) переходы «не работают» - сервер мёртв, вкладка показывает кэш.
- Причина: в корне проекта оказался файл `NUL` (зарезервированное имя Windows, часто создаётся `curl -o NUL` из PowerShell). Vite при `lstat('.../NUL')` падает с `EISDIR`.
- Исправление: файл удалён через `\\.\...\\NUL`; `/NUL` добавлен в `.gitignore`. Middleware больше не ждёт полного чтения HTML перед ответом (streaming probe).

### [ЗАМЕТКА] Медленный переход на Tags/Pages в админке (исправлено 2026-09-03)

- Симптом: клик по Tags/Pages «подвисает», будто идёт долгая блокирующая операция.
- Причины: (1) Vite watcher на Windows мог видеть `data/kv.sqlite3-wal` и делать full reload посреди навигации; (2) на каждой строке списка гидрировался отдельный island `ConfirmDelete`.
- Исправление: абсолютные `server.watch.ignored` для `data/` и sqlite-файлов; один `ConfirmDeleteHost` в admin layout + серверные `ConfirmDeleteTrigger` без JS на строку.

### [ЗАМЕТКА] CSP style-src и Vite CSS (исправлено 2026-09-03)

- Симптом: админка без Tailwind (сетка/флекс не работают), Preview выглядит пустым, Theme/Focus "не реагируют" визуально.
- Причина: `csp({ useNonce: true })` переписывал `style-src` на nonce-only; Vite в dev вставляет `<style>` без nonce, стили блокировались CSP. Островки при этом гидрировались (script-src с nonce ок).
- Исправление: middleware в `main.ts` восстанавливает `style-src 'self' 'unsafe-inline'` после Fresh CSP. Script-src остаётся nonce.
